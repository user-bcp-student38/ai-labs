# HU-01: Protección del token de autenticación

## Origen
- **Componente:** web.
- **H-WEB-01** — Token de sesión almacenado en `localStorage` (estado: Pendiente).
  - Evidencia: `web/src/app/login/login.component.ts:46-49`.
  - Evidencia: `web/src/app/dashboard/dashboard.component.ts:36,75-76`.

## Contexto
- El frontend guarda y recupera el token de sesión en `localStorage`.
- Según la matriz, un script que se ejecute en el mismo origen podría leer y reutilizar el token persistente. El riesgo depende de la exposición a scripts del origen; no se probó un robo de token.

## Ajustes necesarios
- Revisar y ajustar la persistencia y el uso del token para que no quede disponible a scripts del mismo origen mediante `localStorage`.
- Conservar el flujo observado de login, carga autenticada de tareas y cierre de sesión.
- Acordar con los responsables de auth y api el mecanismo y contrato para transportar y gestionar el token; la matriz indica que dichos contratos no se verificaron.

## Criterios de aceptación
- Una prueba de login exitoso verifica que no se persiste el token en `localStorage`.
- Una prueba de carga autenticada verifica que las tareas se pueden solicitar sin leer el token desde `localStorage`.
- Una prueba de cierre de sesión verifica que, al finalizar, no queda el token en `localStorage`.

## Evidencia esperada
- Pruebas automatizadas de login, carga autenticada de tareas y cierre de sesión, con sus resultados.
- Revisión documentada que confirme que el token no está disponible en `localStorage`.
- Contrato acordado con los responsables de auth y api sobre el mecanismo de transporte y gestión del token.
